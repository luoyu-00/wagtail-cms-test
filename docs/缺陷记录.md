## D-01 源与目标指向同一地址时可保存成功，访问形成无限 301 循环

**前置条件**：admin 已登录，重定向模块可访问

**复现步骤**

1. 设置 → 重定向 → 增加重定向
2. 「重定向自」填 `/self-loop/`
3. 「来自站点」保持「全部站点」，「永久」保持勾选
4. 「重定向到任意URL」填 `http://127.0.0.1:8001/self-loop/`
5. 点「创建」
6. 访问 `http://127.0.0.1:8001/self-loop/`

**实际结果**

- 保存成功：HTTP 302 跳回列表，绿色提示「重定向 '/self-loop'已增加」，列表新增 `/self-loop` → `http://127.0.0.1:8001/self-loop/`
- 访问该路径返回 301，`Location` 指向自身；跟随 20 跳仍为 301，curl 退出码 47
- Edge 显示「当前无法使用此页面 / 127.0.0.1 重定向你太多次。/ ERR_TOO_MANY_REDIRECTS」
- 附加验证：`/loop-a/` → `/loop-b/`、`/loop-b/` → `/loop-a/` 两条互指同样保存成功，访问 `/loop-a/` 同样不终止

**预期依据**

同一表单对重复源路径已有校验——再建一条「重定向自 `/self-loop/`」会提示「使用此路径的重定向已被占用。」，说明表单有校验机制，唯独不校验目标与源相同；同系统页面缩略名重复、站点 hostname+port 重复也都会被拦截。目标与源相同属最基础的输入错误。

**影响**：该路径对所有访客 100% 不可用；后台无异常标记，只能逐条停用排查；无数据丢失，删除配置即可恢复。

**定级**：S3。影响面是全部访客，但需人工主动配置才触发，删除即恢复且无数据丢失，不到 S2。

## D-02 中文后台下缩略名重复的校验提示仍为英文

**前置条件**：首页（id=3）已发布，其下已存在页面 `dup-a`，缩略名 `dup-slug`

**复现步骤**

1. 首页 → 添加子页面
2. 标题填 `dup-b`，切到「推荐」标签页，缩略名填 `dup-slug`
3. 点「发布」

**实际结果**

校验生效（未创建页面，库中 `dup-slug` 仍 1 条），但提示语为英文，共 3 处：

| 位置 | 文案 |
|---|---|
| 顶部横幅 | `The page could not be created due to validation errors.` |
| 「缩略名」字段下方 | `The slug 'dup-slug' is already in use within the parent page.` |
| 底部浮动提示 | `There are validation errors, click save to highlight them.` |

**预期依据**

同一次提交里标题留空时，字段提示为中文「必须字段」；`缩略名` 的帮助文本也是中文「用于URL的页面名称，如http://domain.com/work/[my-work]/」。同一控件内的说明与报错应保持同一语言。

**影响**：不阻断操作，换个缩略名即可继续；但中文编辑人员看到英文提示无法判断是「缩略名重复」还是「格式错误」。顶部横幅与底部提示是全局组件，任何校验失败都会出现。

**定级**：S4。

**截图**：[缩略名重复-英文提示](evidence/bug-01-slug-duplicate-en.png)、[同表单中文提示对照](evidence/bug-01-same-form-zh.png)
