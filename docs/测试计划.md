## 1. 测试目标

验证后台 12 个模块、84 个功能点在**功能正确性、权限隔离、状态流转、输入边界**四个维度上是否符合预期，重点保障三条核心链路：

1. **内容生产链路**：登录 → 新建页面 → 保存草稿 → 预览 → 发布 → 前台可访问 → 取消发布
2. **权限链路**：组与权限分配 → 低权限账号能否看到 / 能否越权操作 → 权限变更是否即时生效
3. **审核链路**：编辑者提交审核 → 审核人通过 / 驳回 → 页面状态是否正确流转

其余模块（图片、文档、站点、重定向、集合、账户、报表）以主路径 + 关键边界为主。

### 2.2 不测试范围（及原因）

| 不测内容 | 原因 |
|---|---|
| 性能与并发压力 | 本地 runserver 单进程 + SQLite，不具备压测条件；且非本次目标。并发场景仅做双标签页重复提交的功能性验证，不做量化指标 |
| 安全渗透测试 | 超出范围。仅覆盖常见输入注入字符、越权访问 URL、预览链接未授权访问三类基础风险 |
| 移动端与响应式适配 | 被测对象为桌面端后台管理界面，官方未承诺移动端体验 |
| 内容多语言翻译 | 后台只启用界面语言（区域偏好），未启用内容级 i18n 与多语言页面树 |
| 邮件发送链路 | 本地未配置 SMTP，密码重置只验证页面与表单校验，不验证发信与邮件内容 |
| 富文本编辑器与前端模板渲染细节 | 属于前端组件与主题层，非管理后台业务逻辑；仅验证内容保存与前台可见性 |
| 数据库层与迁移 | 未做 SQL 级校验；SQLite 与生产 MySQL 差异记录为风险 R3 |

## 3. 测试策略

| 层级 | 方式 | 覆盖对象 | 频次 |
|---|---|---|---|
| 冒烟 | 手工 | P0 用例（43 条） | 每次提测前必跑，不通过则停止全量 |
| 功能 | 手工 | 全部 250 条用例 | 第 1 轮全量，第 2 轮针对失败项回归 |
| 权限 | 手工 | viewer01（无组）/ editor01（编辑组）/ disabled01（禁用）与 admin 对照 | 随权限类用例执行 |
| 数据 | 手工造数 + 自造自清 | 命名前缀 `t_`，执行后删除 | 每轮开始前重建 |

**设计方法**：功能点按四象限展开（正例 / 反例 / 边界 / 权限），复杂功能点四类必齐；同一判断分支只保留一条用例。

## 6. 准入 / 准出标准

**准入**

- 服务可启动，登录页可访问（HTTP 200）
- 12 个模块入口全部可访问，无 500
- 冒烟用例（P0 43 条）通过率 ≥ 90%，无阻塞性缺陷

**准出**

| 指标 | 标准 |
|---|---|
| P0 用例通过率 | 100%（允许 1 条标记"已知限制"并说明） |
| 总体通过率 | ≥ 95%（算法：通过数 ÷ (总数 − 未执行数)） |
| S1 缺陷 | 0 条遗留 |
| S2 缺陷 | ≤ 1 条遗留且有规避方案 |
| S3/S4 遗留 | ≤ 3 条，逐条写影响面与规避方案 |
| 文档 | 用例表、缺陷单、测试报告齐全 |

## 7. 风险与应对

| 编号 | 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | 被测系统为开源项目，**无正式需求文档** | 预期结果无权威依据 | 依据优先级：官方文档 > 界面既有行为一致性 > 同类产品惯例 > 我的判断（后者必须标"待确认"并记入待确认清单） |
| R2 | 单人测试，无交叉评审 | 用例遗漏、预期偏差无人纠 | 写完后按四象限矩阵自查 + 抽 20 条复查预期依据；缺陷提交前自查可复现性 |
| R3 | 本地 SQLite，与生产 MySQL 行为可能有差异 | 排序、大小写、并发相关结论可能不适用生产 | 报告中标注环境限制；涉及数据库行为的缺陷标注"需生产环境复验" |
| R4 | 本地无 SMTP | 密码重置/通知邮件无法端到端验证 | 只验页面与校验，明确写入不测范围 |
| R5 | 无压测环境 | 并发与性能问题无法暴露 | 只做功能性重复提交验证；报告注明未覆盖 |
| R6 | 时间紧（单人 6 天） | 覆盖不足 | 优先 P0/P1 与三条核心链路；P3 界面类用例允许"未执行"并如实统计 |
